# Contributing

## Branches and Pull Requests

- Create focused branches for each change.
- Open pull requests into `main`.
- Keep pull requests small enough to review.
- Explain user impact, product boundaries, and verification steps in each PR.

## Architecture Decisions

Architectural changes require an ADR update or a new ADR before implementation. This includes changes to system boundaries, data ownership, import/export flow, offline sync, security model, or deployment architecture.

## Scope Approval

Scheduling, critical-path, recovery planning, resource levelling, automatic date movement, AI prediction, dashboard-builder, native mobile, live Microsoft Project integration, and other scope-expanding features require explicit approval before design or implementation work starts.

## Secrets and Artifacts

Do not commit secrets, `.env` files, uploaded source archives, Microsoft Project files, PDFs, DOCX files, generated exports, local database files, or evidence uploads.
